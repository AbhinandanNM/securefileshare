👥 PPT Slide 5: The 3 System Users & Threat Matrix

1. File Owner (Alice / Abhinandan)
• Uploads & encrypts files (AES-256-CBC)
• Retains exclusive ownership
• Grants & revokes permissions (read/write)
• Has full audit log access
2. Authorized Recipient (Bob / Sushant)
• Granted access by owner via permission record
• Can decrypt and download original file
• Integrity verified automatically before release
• Access terminates immediately upon revocation
3. Unauthorized User / Attacker (Eve)
• Attempts direct download or URL manipulation
• Has NO valid cryptographic permission
• Blocked immediately with HTTP 403 Forbidden
• Recorded in SIEM Audit Trail as attack event

🔄 PPT Slide 7: The 3 Core Cryptographic Workflows

Workflow 1: Upload

1. Authenticate (JWT Bearer Token)
2. Check Access (Valid authenticated user)
3. Protect File (Compute SHA-256 hash + AES-256-CBC encrypt with random DEK + Wrap DEK with Master KEK)
4. Store (Ciphertext saved to uploads/<uuid>)

Workflow 2: Download

1. Authenticate (Validate JWT session)
2. Check Access (Is Owner OR Valid Active Share?)
3. Verify / Decrypt (Unwrap DEK + Decrypt ciphertext + Verify SHA-256 digest match)
4. Download (Deliver decrypted original payload)

Workflow 3: Sharing & Revocation

1. Owner selects target file
2. Select Recipient (username)
3. Set Permission (Read or Read/Write + optional expiry)
4. Grant Access (Record delegation in DB)
5. Revoke (Owner flips revocation flag; instant 403 block)

🎯 PPT Slide 3: Objectives O1–O5 Implementation Matrix

O1

Authenticated Access

Registered users only. Protected via bcrypt (12 rounds) salted password hashing and stateless JWT (HMAC-SHA256) bearer tokens with 24-hour expiry.

O2

File Confidentiality

Stored files unreadable without decryption. Protected via AES-256-CBC with PKCS#7 padding and Two-Tier key hierarchy (per-file DEK wrapped with Master KEK via PBKDF2).

O3

Integrity Protection

Detect any file tampering. Pre-storage SHA-256 cryptographic digest verified upon every download. If 1 bit is altered, download is aborted with HTTP 409.

O4

Secure Communication

Data protected in transit. Client-server requests served over HTTPS / TLS 1.3, eliminating Man-in-the-Middle (MitM) eavesdropping and packet sniffing.

O5

Permission-Based Sharing

Revocable access control. Granular read and write permissions with optional timestamped expiry and one-click instant revocation.
