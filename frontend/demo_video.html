Slide 2 · Problem Statement

The Cloud Security Dilemma

Standard cloud storage platforms store user payloads in plaintext or delegate keys to the cloud provider, exposing files to unauthorized access, side-channel leaks, and silent tampering.

🚨 Vulnerability 1: Plaintext at Rest
If server disks or snapshots are accessed by third parties or rogue administrators, confidential documents are instantly compromised.
⚠️ Vulnerability 2: Undetected Bit Tampering
Without cryptographic integrity digests, deliberate byte alterations or bit-rot cannot be detected prior to user consumption.
🔒 Our Engineered Solution
Zero-trust architecture combining AES-256-CBC, PBKDF2 Master KEK, SHA-256 digests, and instant cryptographic revocation.
Slide 3 & 4 · Cryptographic Objectives

Five Core Cryptographic Objectives

Every objective outlined in our Review 1 presentation is rigorously enforced in code:

O1 Authenticated Access
bcrypt (cost 12) + 24-hr stateless JWT HMAC-SHA256 tokens. Prevents unauthenticated entry.
O2 File Confidentiality
AES-256 in CBC mode with random 256-bit DEK per file, wrapped by Master KEK via PBKDF2 (100k rounds).
O3 Cryptographic Integrity
Pre-storage SHA-256 digest verified on every download before decryption. Instant tamper rejection.
O4 In-Transit Security
TLS 1.3 / HTTPS encryption guarding all REST endpoints and payloads over the network.
O5 Revocable Sharing
Granular read/write permissions, ISO expiry dates, and immediate server-side revocation.
Slide 6 & 7 · Key Hierarchy & Architecture

Two-Tier Key Hierarchy & Storage Flow

Enterprise-grade key encapsulation prevents key re-use and protects against compromised disk snapshots.

1. Master Secret Application KEK Secret
➔
2. PBKDF2 (100k) Derived Master KEK
➔
3. Random DEK & IV Unique 256-bit Key / File
➔
4. AES-256-CBC Ciphertext Chunk on Disk
🛡️ Disk Safety: Plaintext DEK is never stored on disk. It is encrypted with the Master KEK and stored as files.encrypted_key.
